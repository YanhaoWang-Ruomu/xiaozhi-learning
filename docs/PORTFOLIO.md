## 已测量的结果

2026-10-08 的原始记录在2026-10-09离线重算；保留题目、回答、工具结果及失败案例。完整数字和口径在 JSON 中。

| 检查 | 样本与结果 | 说明 |
|---|---|---|
| 混合检索与专用重排 | 20道正例平均证据召回97.5%→100%；4道无关题两者误接纳均0 | 对同一固定题集比较，改善题号R20 |
| 重排成本 | 24次专用排序平均额外耗时1367.3ms | 体现质量和延迟的取舍 |
| 多轮预约流程 | 同步与流式各6组、11轮通过场景检查与原文复核 | 每份10轮程序预约，1轮真实模型资料问答 |
| 工具有效返回 | 每份7/8；非注入调用7/7 | 分母为实际工具执行；失败的一次为注入 QUERY_FAILED |
| 程序预约耗时 | 同步10轮平均61.4ms、P95 212.5ms；流式10轮平均63.4ms、P95 222.3ms | 记录轮次耗时，未混入模型知识问答 |
| 模型资料问答耗时 | 同步单次9289ms；流式单次4548ms | 各仅1个样本，不能代表稳定分位数；未测首token延迟 |
| 纠错独立挑战 | 11/12通过，H11预期FOUND、实际INSUFFICIENT | 保留失败，纠错默认关闭 |

工具有效返回率核对结构化状态；工具选择是否合适、回答是否忠实和最终数据库状态分别核验。故障注入应正确停止而不是伪造成功。混合检索证据召回和业务状态通过都不替代医疗准确率。

## Python 服务实测

2026-10-09在 Windows / Python3.14.7 下，实际启动本机 Uvicorn，通过 HTTP 提交离线评测并读取结果。单个任务成功，重复键返回同一任务。30次连续健康HTTP请求（其中26次配套状态查询为RUNNING）：平均1.26ms、P95 1.76ms；提交38.75ms，任务286.87ms。原始数字见 [python-http-smoke.json](../evals/portfolio/20261009/python-http-smoke.json)。

这30次请求不是并发负载测试，耗时不代表云模型性能。16项自动检查另覆盖并发重复提交、队列限额、失败和重启恢复。CI 会在两个系统重新执行，分别保留报告。

## 复现与失败分析

1. 克隆仓库，按 Python README 安装固定依赖。
2. 运行 `python -m xiaozhi_eval.metrics --output <输出目录>`，读取原记录并重新计算指标；无模型收费和业务写入。
3. 运行 `pytest` 及 `python smoke.py <输出目录>`，检查任务接口、独立进程和持久化。
4. 按 DEMO.md 录制界面交互；按 RUNBOOK.md 启动实际小智，演示云模型与真实演示业务。
5. 若要重新测量云模型，使用 [检索评测](AI_EVALS.md)、[多轮评测](AGENT_MULTITURN_EVALS.md)、[专用排序](DEDICATED_RERANK.md) 及对应脚本。先按各文档检查账户、隔离数据库与费用条件，再运行；普通 CI 不自动调用云模型。

原始记录还保留早期多轮失败、纠错召回下降和 H04 改写超限。这些记录用于解释为什么加入阶段工具约束、程序预约路径与受限纠错开关。完整实现状态见 [Agent六方向](AGENT_DIRECTIONS.md)。

## 后续学习

机器学习实验暂缓。现有小题集适合回归和方案对照，尚不足以支撑可靠的训练、验证、测试划分；未将无关的银行意图数据训练成绩写成医疗项目成果。后续若积累独立标注的路由或检索相关性数据，再比较规则基线、轻量模型和当前方案，并保留训练划分、过拟合与误差分析。
