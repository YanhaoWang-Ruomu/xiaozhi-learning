# 纠错式 RAG 实验

当前结论：实现和回归测试已完成，真实效果未达到默认启用标准。默认关闭，继续使用已有混合检索。新增能力不等于应立即替换稳定方案。

## 流程

CorrectiveKnowledgeService 接收现有混合检索选出的最多两个片段，再调用只读 Qwen 检查器判断能否回答原问题。充分时仅将经过逐字校验的引用送入生成上下文，保留原文件来源与片段编号。资料不足时可改写一次并重新检索，再对照原问题检查；仍不足则澄清。明确冲突、格式错误或基础设施异常停止，不无限重试。

检查器没有业务工具。引用必须来自提供的片段，禁止不存在的编号、重复引用和伪造文本；将省略号插入所谓逐字引文也会被拒绝。改写不能改变 ASCII 编号或数字，原问题带否定词时保守地拒绝改写。这只是局部约束，不能证明中文实体及完整语义完全等价。

当实验开关启用时，聊天仅对有限医院资料、服务和流程词汇进入纠错检查。程序预约分流优先，普通问候和被识别出的症状、药物类问题沿用原链路。词汇筛选不是完整意图分类或医疗风险识别。

依据不足、冲突或检查失败时，回复与本轮随机标记绑定，由同步/流式入口直接给出保守说明，不再让生成模型补写具体事实。跨会话及旧轮次结果不能沿用。成功时检查后的引文仍交给原有模型回答，因此不等于具备通用事实核验能力。

## 开关与复现

默认配置：xiaozhi.rag.corrective.enabled=false。

仅实验时可在 Spring Boot 启动参数设置 --xiaozhi.rag.corrective.enabled=true，或配置环境变量 XIAOZHI_RAG_CORRECTIVE_ENABLED=true；关闭后恢复原检索。开关影响聊天增强，既有 /api/knowledge/search、工程实验页和 MCP 检索接口未替换。

离线检查：

```powershell
cd F:\xiaozhi-learning
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-corrective-rag.ps1 -JavaHome "F:\xiaozhi-medical\tools\jdk\jdk-17.0.20.1+1" -MavenCommand "F:\xiaozhi-medical\tools\maven\apache-maven-3.9.11\bin\mvn.cmd"
```

命令增加 -Live 才调用真实 Qwen、向量模型和 Pinecone，需要已有 DASHSCOPE_API_KEY、PINECONE_API_KEY、PINECONE_INDEX_HOST。只读现有知识命名空间，不自动同步或修改业务库。结果写入新的 evals/results/corrective-rag-时间戳目录，不覆盖历史记录。

未来评测会因召回下降、误接受增加、执行错误或缺少题目而返回非零退出码。通过该固定样本门槛仍需人工复核与独立题集，不自动打开生产开关。

## 真实对照结果

固定题集仍为 retrieval-v1.jsonl，SHA256 为 e0e8eae18a67dde3cd58ed6cedcf9db123187681943687cdde7a4413fa1784b7。每版均完整运行 24 题，其中20题有依据、4题无关。首轮候选由前后方案共享，避免重复检索造成不公平差异；改写后的检索实际调用现有混合检索。

| 版本与报告目录 | 原方案平均证据召回 | 纠错后 | 无关题误接受数（前/后） | 检查失败 |
|---|---|---|---|---|
| 初版：corrective-rag-20261008-171158 | 97.5% | 82.5% | 0/0（分母均为4） | 0 |
| 否定答案规则修正版：corrective-rag-20261008-171618 | 97.5% | 92.5% | 0/0（分母均为4） | 1 |

召回按所选证据对应的原始语料片段计算，不要求短引用包含整句金标准；它衡量证据身份覆盖，不是最终回答准确率。题集未修改，原始判断、尝试、来源和版本快照均保留。两版均未达到启用门槛，不能只展示修正版更高的数字而省略基线。

初版错误拒绝了R05、R06和R11中的否定依据。修正版修复了部分误判，但R06把省略号加入逐字引文，程序按规则拒绝；R20只覆盖两个问题中的一个，检查器却判为充分，说明依据完整性判断仍有缺口。R01额外选择了轮椅服务台片段，也需继续检查不相关依据的干扰。

初版有四次重查后得到充分判断，但不代表新增了四题正确依据；修正版没有重查恢复的正例。两版每题整个对照流程平均约5.51秒、4.43秒，包含原检索和检查，不能称为净增加延迟。最多两次检查与两次检索会增加调用成本，最终生成调用另计。日志可追踪 retrieval.corrective、retrieval.evidence_check 以及状态、尝试数、失败类别。

该对照强制调用检索层，包含生产聊天可能绕过的题目；不能直接当成完整聊天准确率或线上路由分布。检索夹具、最终回答、临床安全、开放语言表达和稳定性需要独立验收。

后续优先补充未见过的不足、冲突、多问题题集，比较结构化证据抽取或独立评估器，再决定是否启用；专用重排序与官方Agentic对照仍是单独任务。
