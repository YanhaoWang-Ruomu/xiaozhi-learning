# 学习路线

目标：能够自己实现、运行并解释项目，然后根据实际问题做改进。

| 阶段 | 要理解和实现的内容 | 完成标准 | 视频参考 |
|---|---|---|---|
| 0 | Git、GitHub、项目说明与学习记录 | 第一条提交推送成功 | 学习准备 |
| 1 | Java、JDK、Maven、Spring Boot | 自己创建项目并启动一个最小接口 | 01–06 |
| 2 | 模型 API、API Key、LangChain4j、AIService | 能解释并完成一次真实模型请求 | 07–19 |
| 3 | 会话记忆、会话隔离、MongoDB | 多轮对话与持久化验证通过 | 20–31 |
| 4 | 系统提示词、参数与助手接口 | 能解释助手行为由哪些代码决定 | 32–40 |
| 5 | 工具调用、MySQL、预约业务 | 查询、确认、取消逻辑及测试通过 | 41–48 |
| 6 | 文档解析、分块、向量、RAG、Pinecone | 能展示问题、检索结果与回答依据 | 49–64 |
| 7 | 流式输出与 Vue 前端 | 从网页走通主要交互 | 65–66 |
| 8 | 问题评估与改进 | 每项改进有原因、代码和验证记录 | 基础版完成后 |

视频分组基于已核对的文件名称，不表示已经观看全部内容。
每次只推进一个可以解释和验证的小步骤，不要求一次学完全部技术。

## Git 习惯

1. 修改前查看 git status，确认当前分支和已有变更。
2. 完成一个有意义的小步骤后检查 git diff。
3. 显式选择本次要提交的文件，检查暂存内容。
4. 创建清楚说明变化的 commit，再 push 到 GitHub。
5. 在学习记录中记下理解、问题、解决方法和验证结果。

后续有独立改进功能时再学习分支和 Pull Request。
