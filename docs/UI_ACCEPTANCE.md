| 检查 | 验证方式 |
|---|---|
| 登录、会话搜索、快捷输入 | 真实 Chromium 点击与输入，确认未额外发送消息 |
| 重复发送与来源显示 | 完整 SSE 传输，检查单次 POST、文本转义与资料展开 |
| 中途断网与恢复 | Chromium context.setOffline，中断接收后后端继续完成，联网同步与刷新均不重发 |
| 主动停止接收 | 取消浏览器接收，再刷新找到唯一一份已保存回复 |
| 预约确认与取消 | 手机宽度下先生成草稿、再复核、再最终确认；取消后刷新保留取消状态 |
| 实验页 | 独立页面运行检索并显示接口返回片段 |
| 布局 | 320、390、768、1024、1440像素视口；无页面横向溢出 |

## OTLP补充

新增本地HTTP接收测试，验证实际protobuf导出、Authorization头、同一traceId、操作名，以及敏感正文未进入导出内容。另测非法地址、换行注入和接收端401；导出失败不使业务调用失败。BatchSpanProcessor的forceFlush完成不代表接收端已经成功入库，验收以接收端实际观测为准。

配置可选环境变量：

- XIAOZHI_OTEL_ENDPOINT：完整的OTLP HTTP traces接收地址。
- XIAOZHI_OTEL_AUTHORIZATION：平台要求的完整Authorization值，通过环境变量或安全配置注入，不写入版本库。

远程接收地址必须为HTTPS，禁止在URL用户名、查询串或片段中放凭据。本地接收测试使用临时端口和无效测试鉴权值。
Langfuse的Java接入可使用OTLP HTTP；官方说明：https://langfuse.com/integrations/native/opentelemetry 。本项目尚未配置Langfuse项目凭据，未验收云端展示、数据保留规则或其特有属性映射。不能把本地OTLP通过当作Langfuse云项目通过。
