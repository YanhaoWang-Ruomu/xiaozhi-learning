# 服务端聊天历史与会话列表

## 存储与接口

- `chat_conversations`：会话编号、标题、创建时间、浏览器访问密钥的 SHA-256 摘要。
- `chat_history_turns`：每轮一条文档，保存用户消息、最终回复、完成状态和检索来源。避免将无限增长的历史塞进单个 MongoDB 文档。
- `chat_memory`：继续由 LangChain4j 管理有限记忆窗口；查询完整历史不会把全部历史重新塞给模型。
- `POST /api/conversations`：创建或关联当前浏览器的会话。
- `GET /api/conversations?limit=20&before=...`：按创建时间从新到旧分页列出当前浏览器的会话。
- `GET /api/conversations/{id}/messages?limit=20&before=...`：每页最多20轮，页面可加载更早记录。
- 会话接口要求 `X-Conversation-Key`；Vue 的聊天请求也携带该密钥。服务端按归属过滤列表，校验读取和写入，不能用另一密钥访问已有会话。

## 行为与边界

- 流式回复真实完成后，先保存历史再发送 done。客户端断开不会自动重发聊天，后台完成后可以同步找回。
- 失败或进程重启遗留的未完成请求显示为未完成，不伪造完整回复。未完成的部分 token 暂不持久化。
- 当前使用单后端实例；处理中状态结合当前实例的活动请求判断，多实例部署前需要改为共享租约。
- 浏览器只保存访问密钥和当前会话位置，聊天正文由服务端读取。切换会话同时重新查询对应草稿。
- 请固定使用 `http://127.0.0.1:5173/`。localhost、不同浏览器和无痕窗口使用不同站点存储，不会自动共享会话。
- 清除网站数据会删除访问密钥，当前尚未提供密钥恢复或正式账号登录。密钥不要发给他人。
- 浏览器密钥隔离只覆盖本阶段聊天历史与聊天写入，不代表预约、草稿等全部业务接口已完成用户权限隔离；完整登录与数据归属仍是后续阶段。
- 旧版完整历史不能从有限模型记忆中完整重建。可关联当前标签页旧会话编号及草稿，旧 sessionStorage 缓存不删除，但不作为可信服务端历史自动导入。
